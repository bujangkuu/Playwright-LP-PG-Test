## 1. Requirement Summary (Ringkasan Kebutuhan Bisnis)

Fitur **`Insert RC68`** dirancang sebagai antarmuka dan backend pemrosesan data rekonsiliasi transaksi QRIS yang telah berstatus *settled*. Fitur ini memungkinkan pengguna internal (Internal Admin) untuk mengunggah file laporan transaksi settlement (format CSV RC68) ke dalam sistem Payment Gateway, memvalidasi integritas data, menyeleksi transaksi yang akan diproses, mengonfirmasi eksekusi transaksi, dan menyajikan ringkasan hasil pemrosesan (berhasil vs gagal).

### Ruang Lingkup Pengujian:
1. **Antarmuka Upload RC68**:
   * Komponen drag-and-drop / selector file untuk mengunggah file RC68 berformat `.csv`.
   * Indikator informasi file terpilih (Nama file, ukuran file, icon CSV, dan tombol hapus/batal `x`).
   * Tombol aksi **`Import`** (berstatus disabled saat file belum dipilih, dan aktif saat file CSV valid terpilih).

2. **Validasi & Pemrosesan File CSV (Backend & Parser)**:
   * Validasi ekstensi dan MIME type file (hanya menerima file `.csv`).
   * Validasi struktur header dan 10 kolom wajib standar RC68:
     `Date,Time,RRN,Terminal_ID,Merchant_PAN,Issuer,Amount,MID,NMID,MTN`
   * Validasi baris data (tipe data numerik untuk `Amount`, `RRN`, format tanggal `DD/MM/YYYY`, validitas `NMID`/`MID`).
   * Pencegahan duplikasi data transaksi (idempotensi berbasis `RRN` / `MTN`).

3. **Daftar Transaksi RC68 (`List Transaction RC68`) & Seleksi Ceklis**:
   * Menampilkan data transaksi RC68 yang telah berhasil diimpor ke dalam tabel.
   * Kolom tabel: `Checkbox`, `Date Time`, `MPAN`, `RRN`, `Amount` (format Rupiah `Rp`), dan `MTN`.
   * Kontrol master checkbox di header (pilih semua / batalkan semua baris) serta checkbox individu pada setiap baris.
   * Kontrol pagination: dropdown ukuran halaman (`Show 10`, `Show 25`), counter data (`Showing 1-X of Y items`), navigasi halaman (`Previous`, nomor halaman, `Next`).

4. **Aksi Eksekusi, Konfirmasi, & Pembatalan (UI Workflow)**:
   * Tombol **`Proceed`** (aktif jika minimal 1 baris tercentang, disabled jika 0 baris).
   * Tombol **`Cancel`** pada halaman utama (mereset seluruh centang checkbox).
   * Dialog Modal **`Confirm`** dengan pesan konfirmasi *"Are you sure you want to process this transactions?"*, tombol **`Cancel`**, dan tombol **`Process`**.

5. **Visualisasi Hasil Pemrosesan (Popup Notifikasi & Pemisahan Tabel)**:
   * Floating popup notifikasi di kanan bawah: **`Process Completed`** dengan task title *"Execute Insert RC68"*, tanggal eksekusi, progress bar 100% (*X/Y*), badge hijau **`Successful N`**, badge merah muda **`Failed M`**, serta tombol close (`x`).
   * Pemisahan tabel hasil di halaman utama menjadi **`Successful (N)`** dan **`Failed (M)`** lengkap dengan rincian kolom transaksi.

6. **Keamanan & Hak Akses (PBAC/RBAC & Audit Logging)**:
   * Pembatasan hak akses berbasis permission `qris_rc68.insert` yang secara eksklusif hanya dimiliki oleh role bertipe **`INTERNAL`**.
   * Penolakan akses untuk role eksternal (`ORGANIZATION` dan `MERCHANT`) dengan `HTTP 403 Forbidden`.
   * Pencatatan `audit_logs` secara otomatis untuk setiap aktivitas upload dan eksekusi RC68.

## 2. Requirement Clarification & Gap Analysis

| No | Poin Analisis / Potensi Celah | Temuan & Rekomendasi QA | Tindakan Mitigasi |
|---|---|---|---|
| 1 | **Batas Maksimum Ukuran & Jumlah Baris File** | PRD belum mencantumkan batas ukuran maksimum file CSV (misal: 10MB atau 50.000 baris transaksi). | QA menetapkan batas uji boundary: file 5 MB, 10 MB, dan validasi timeout upload pada koneksi lambat. |
| 2 | **Penanganan Parsial (Partial Failure vs Atomic Transaction)** | Jika terdapat baris invalid, apakah transaksi di-rollback atau baris valid tetap diimpor? | Hasil eksekusi memisahkan secara visual baris berhasil ke tabel Successful dan baris gagal ke tabel Failed. |
| 3 | **Pencegahan CSV Injection (Formula Injection)** | File CSV dari pihak eksternal dapat memuat formula jahat seperti `=cmd|' /C calc'!A0` atau `+` / `-` / `@` pada kolom teks (`Terminal_ID`, `MTN`). | Backend parser wajib membersihkan (*sanitize/strip*) karakter awalan formula sebelum diproses dan ditampilkan ke UI. |
| 4 | **Format Tanggal & Jam Gabungan** | Di file CSV, tanggal dan waktu dipisah (`Date` & `Time`), namun di UI tabel ditampilkan gabung sebagai `Date Time` (`DD/MM/YYYY HH:mm:ss`). | QA memverifikasi akurasi parsing dan penggabungan zona waktu (WIB/UTC) agar tidak terjadi pergeseran tanggal. |
| 5 | **Duplikasi Data Transaksi (Duplicate RRN/MTN)** | Unggah ulang file yang sama berpotensi menyebabkan double balance / double settlement jika tidak ada deduplikasi. | Backend harus menolak atau mengabaikan transaksi dengan kombinasi unik `RRN` + `MTN` yang telah tercatat sebelumnya di DB. |

## 4. Risk Analysis & Mitigation Strategy (Analisis Risiko Produksi)

| Risiko Pengujian | Tingkat Keparahan | Dampak | Rencana Mitigasi QA |
|---|---|---|---|
| **Data Integrity & Double Settlement** | **CRITICAL** | Jika baris transaksi RC68 yang sudah settled dimasukkan dua kali tanpa deduplikasi unik, saldo settlement merchant dapat berlipat ganda (*over-crediting*). | Wajib menguji kombinasi unique constraint `RRN` + `MTN` pada database dan idempotency token pada upload request. |
| **Privilege Escalation via Direct API** | **HIGH** | User organisasi atau merchant memanggil endpoint internal untuk memanipulasi data rekonsiliasi. | Memverifikasi enforcement permission `qris_rc68.insert` pada gateway dan menolak seluruh user non-internal dengan `HTTP 403`. |
| **Race Condition pada Eksekusi Batch** | **HIGH** | Pengguna menekan tombol Process berkali-kali saat koneksi lambat, memicu eksekusi ganda terhadap baris transaksi yang sama. | Menerapkan proteksi tombol disabled/loading di frontend dan mutex lock / status guard `IN_PROGRESS` di backend. |
| **Server Timeout & Denial of Service (DoS)** | **HIGH** | File CSV berukuran puluhan megabyte dengan jutaan baris dapat menguras CPU server atau membuat database lock berkepanjangan. | Menerapkan pengujian boundary limit (maksimal 10 MB), validasi streaming parser CSV, dan verifikasi rate limit upload. |
| **CSV Injection / Stored XSS** | **MEDIUM** | Karakter khusus atau script formula dalam metadata merchant/transaksi yang dirender pada antarmuka admin. | Menerapkan sanitasi input dan escaping otomatis pada seluruh teks kolom tabel sebelum ditampilkan ke DOM. |
